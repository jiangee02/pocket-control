# 开发与发布

## 环境

- JDK 17（AGP 8.7.3 的最低要求）
- Android SDK 35、Build-Tools 35.0.0
- Gradle 8.9（仓库自带 Wrapper）
- Node.js 16+（中继与 e2e）

## 构建被控端

```bash
cd android-app
./gradlew :app:assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

- `master-web/` 通过 `app/build.gradle.kts` 的 `assets.srcDir("../master-web")` 打进 APK；改完网页必须重新构建。
- 中继部署使用的是 `relay-server/`，改完 `master-web/` 后同步复制到 `relay-server/public/`，否则中继仍是旧页面。
- 离线构建指定本机 aapt2：

```bash
gradle :app:assembleRelease --offline \
  -Pandroid.aapt2FromMavenOverride=/path/to/Android/Sdk/build-tools/35.0.0/aapt2
```

## 版本

当前配置在 `android-app/app/build.gradle.kts`：

```kotlin
versionCode = 200
versionName = "2.0.0"
```

- `versionCode` 必须是大于上一版的整数，不能复用；`versionName` 仅用于展示。
- 2.0.0 的 `versionCode` 为 200，旧版 1.0.69 为 68，可直接覆盖升级。

## 签名

`android-app/keystore.properties`（已在 `.gitignore`）：

```properties
storeFile=release.keystore
storePassword=你的密码
keyAlias=你的别名
keyPassword=你的密码
```

- 同一 `applicationId` 必须使用同一密钥签名，否则无法覆盖安装。
- keystore 丢失后无法更新已安装用户；泄露后可被用来伪造同签名更新。离线备份，禁止提交。
- 签名只校验来源与完整性，不加密 APK，也不隐藏代码。
- 自编译 APK 的签名与官方版不同，不能覆盖官方版；如需无缝升级，使用同一份 keystore。
- 发布前核对证书：

```bash
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

官方 v2.0.0 证书 SHA-256：

```text
59d699e12e951ad512bc053e9995ba877d1ab58277bd485327374bc5183e0082
```

首次生成密钥：

```bash
keytool -genkeypair -v -keystore release.keystore -alias pocketcontrol \
  -keyalg RSA -keysize 4096 -validity 10000
```

已发布过旧版本时不要重新生成，继续使用原 keystore。

## 自检

```bash
node e2e/test-protocol.js      # 加密互操作 + 中继管道
node e2e/test-pure-crypto.js   # 纯 JS 加密回退
node e2e/test-touch-chain.js   # 触控队列（需 JDK 与 Gradle 本地库）
node e2e/mock-host.js          # 模拟被控端，浏览器打开 http://127.0.0.1:9390
```

`mock-host.js` 可接一个 H.264 Annex-B 文件做真实画面；仓库不附带样本文件。

## 中继打包与部署

```bash
cd relay-server
npm install
node relay.js          # 默认 8787，PORT 可覆盖
```

- 放行 TCP 8787；建议用 pm2 或 systemd 常驻。
- HTTPS 可用 Caddy 或 Nginx 反代 8787；Nginx 需配置 WebSocket 的 `Upgrade` 头。
- `python scripts/pack_relay.py` 生成带依赖的部署 zip（打包的是 `relay-server/`）。

## 第三方组件

| 组件 | 用途 | 许可证 |
|---|---|---|
| NanoHTTPD 2.3.1 | 内置 HTTP / WebSocket 服务 | BSD-3-Clause |
| OkHttp 4.12.0 | 中继模式客户端 | Apache-2.0 |
| ZXing core 3.5.3 | 二维码 | Apache-2.0 |
| AndroidX core-ktx / appcompat | Android 基础库 | Apache-2.0 |
| Shizuku api / provider 13.1.5 | 授权与系统级调用 | MIT |
| ws 8.22.1 | 中继 WebSocket | MIT |
| JMuxer | 浏览器 H.264 封装 | 仓库未标注 SPDX，发布前需确认 |

- 分发 APK 或中继 zip 时保留各依赖的 LICENSE / NOTICE；Apache-2.0 组件附带的 NOTICE 一并保留。
- JMuxer 的压缩文件没有许可证头，仓库也未标注 SPDX。未确认前不要对外声明整个项目只含 MIT 依赖；无法确认时替换为许可证明确的封装库。
- Gradle、AGP、Kotlin 等构建工具不随 APK 分发，但源码构建仍需遵守各自许可。

## 许可与署名

- 项目使用 MIT，分发源码或 APK 都必须保留 `LICENSE` 中的版权与许可声明。
- 衍生项目需在 README 或「关于」页注明基于随手控（原作者 jiangee02）开发，并附项目地址。
- 不得暗示原作者为修改版背书；修改版应更换名称与图标，避免与官方版混淆。
- MIT 不要求在 App 界面内显示作者。需要强制界面署名时，自行增加「关于」页，或改用带附加署名条款的许可证。
- 如需衍生版本必须开源，在发布前改用 GPL-3.0；已按 MIT 发布的版本不能收回授权。

## 发布清单

1. 递增 `versionCode`，更新 `versionName`。
2. 构建 release，`apksigner verify --print-certs` 核对证书指纹。
3. 计算 APK 的 SHA-256，写入发布说明。
4. `deliverables/` 只保留当次 APK 与最新中继 zip，旧版本删除。
5. 打 tag，发布说明包含版本号、变更、证书指纹、APK SHA-256。
6. 确认 `keystore.properties`、`*.keystore`、`local.properties` 未被提交。
